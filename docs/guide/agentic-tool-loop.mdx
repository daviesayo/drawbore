---
title: "Agentic tool loop: let the model use tools, safely"
description: "A model-backed agent that declares tools can call them mid-completion — every call through the proxy and a one-time token, any failure halts, the loop is bounded, and Drawbore validates the final answer."
---

A model-backed agent can do more than one shot. When it **declares tools**,
Drawbore runs it as a bounded tool loop: the model calls a tool, sees the result,
and continues — until it returns a final answer that Drawbore validates against the
agent's output schema. The orchestration engine is hidden; you write an ordinary
agent.

```python
from drawbore import Pipeline, agent
from drawbore.orchestration import ADKEngine
from drawbore.llm import LLMRuntime, LLMRuntimeConfig, ModelProfile, ModelTarget, ProviderConfig

@agent(name="screen", input=Transactions, output=Verdict, model="gpt-4o", tools=["risk_lookup"])
async def screen(txns, tools):
    ...  # the function body is not run on the model path

runtime = LLMRuntime(config=LLMRuntimeConfig(
    profiles={"default": ModelProfile(targets=(
        ModelTarget(provider="openai", model="gpt-4o"),
    ))},
    providers={"openai": ProviderConfig(credential_env="OPENAI_API_KEY")},
))

p = Pipeline(name="aml", registry=registry)
p.add(screen)
result = await p.run(transactions, engine=ADKEngine(llm_runtime=runtime))
```

Every tool call the model makes goes through the same proxy and single-use token as
any other Drawbore tool — only the agent's *declared* tools exist, and the call is
traced and audited. The model never gets to route around a control:

- **Any tool failure or denial halts** the step and escalates with a legible reason
  — the loop does not "recover" around a tripped control. A proxy denial keeps its own
  halt code (for example `taint_violation` when the
  [taint breaker](/guide/taint-and-trust) refuses an exfil-capable call, `token_violation`,
  or `circuit_breaker`).
- **The loop is bounded** (`max_llm_calls`, default 8) — a runaway loop halts.
- **Drawbore owns the answer** — the model's final output is parsed and validated
  against your output model. A model that declares tools cannot be pinned to JSON-only
  output on its final turn (forcing structured output and offering tools are mutually
  exclusive), so a model that narrates before answering may wrap its JSON in prose. If
  the final answer holds exactly one top-level JSON object, Drawbore extracts it
  deterministically and the step proceeds — a pure re-parse of what the model already
  said, so no tool is re-invoked. If it holds no JSON object, or more than one
  (ambiguous), the step fails closed and halts `model_error` with a bounded excerpt of
  the offending content; Drawbore never guesses which object to trust.

The number of model turns and every tool call are in the audit trail:

```python
step = result.audit_trace.step_records[0]
print(step.model_turns)   # e.g. 3
print(step.tool_calls)    # ('risk_lookup (invoke) -> ok', ...)
```

A tool ref the model cannot name verbatim still works. Function-calling providers
restrict a tool's name to letters, digits, `_`, and `-`, so a ref like
`mcp://sanctions_feed/latest_updates` or `evidence://retrieve` cannot be sent as-is.
Drawbore exposes each such tool to the model under a provider-safe alias and resolves
the alias the model picks back to the canonical ref before the call runs. You keep
writing the canonical ref; scope enforcement, the one-time token, the proxy log, and
the audit trail all stay keyed on the canonical ref (the alias is only the name the
provider sees).

The loop only ever offers the model the agent's *declared* tools. A call to anything else —
an invented alias that maps to no declared tool, or a tool that is registered but not declared
by this agent — never reaches the proxy, so it does not produce a proxy scope denial. It fails
closed at the model boundary and halts `model_error`. (A deterministic agent that calls a
registered-but-undeclared tool directly halts `tool_access` instead — same fail-closed outcome,
different halt code.) For loop steps, alert on `model_error` for this case; see
[Taint and trust](/guide/taint-and-trust) for how the breaker's `taint_violation` carries over
to loop-invoked tools, and [Branching on a halt](/guide/reliability#branching-on-a-halt) for the
full vocabulary.

This composes with evidence compression: a compressed step's model can retrieve the
full original mid-loop with the `evidence://retrieve` tool — scoped by the proxy, a
handle is not authority.

You supply a model-capable engine (today, `ADKEngine`). A model-backed agent run on
an engine with no model path fails closed with a legible error. Model fallback
inside the loop, streaming, and parallel tool calls in one turn are not in Phase 1
(a loop agent uses its primary model; declaring `fallback_model` fails closed).
