---
title: "Production LLM gateway: profiles, providers, and fallback"
description: "Declare the model capability an agent needs; let a deployment choose the provider. One LLMRuntime owns profile resolution, credential checks, provider-attempt classification, fallback, and audit — without leaking provider detail into your pipeline."
---

An agent declares the model capability it needs. A deployment decides which provider
serves it. The agent contract never changes, and no provider detail leaks into the
pipeline manifest.

```python
@agent(input=Tx, output=RiskScore,
       model="profile:judgment",
       fallback_model="profile:judgment_backup")
async def score(tx: Tx) -> RiskScore: ...
```

`model="profile:<name>"` resolves `<name>` from runtime config. Any other string is a
direct model string (e.g. `"openrouter/anthropic/claude-3-5-sonnet"`). The explicit
`profile:` prefix is required — Drawbore never guesses whether a bare string is a
profile or a provider model.

You build the runtime policy as typed data and hand it to the engine:

```python
from drawbore.llm import LLMRuntime, LLMRuntimeConfig, ModelProfile, ModelTarget, ProviderConfig
from drawbore.orchestration import ADKEngine

runtime = LLMRuntime(config=LLMRuntimeConfig(
    profiles={
        "judgment": ModelProfile(targets=(
            ModelTarget(provider="openrouter", model="anthropic/claude-3-5-sonnet"),
            ModelTarget(provider="openai", model="gpt-4o"),
        )),
        "judgment_backup": ModelProfile(targets=(
            ModelTarget(provider="openai", model="gpt-4o"),
        )),
    },
    providers={
        "openrouter": ProviderConfig(credential_env="OPENROUTER_API_KEY"),
        "openai": ProviderConfig(credential_env="OPENAI_API_KEY"),
    },
))
result = await pipeline.run(input, engine=ADKEngine(llm_runtime=runtime))
```

**One runtime, one authority.** The `LLMRuntime` owns profile resolution, credential
checks, provider-attempt classification, fallback, and the gateway/model-factory both
the one-shot and the model+tools paths use. There is never a second config object.

**Provider settings apply to every path.** A `ProviderConfig` may set `base_url`,
`timeout_seconds`, and `extra` (a pass-through for provider parameters Drawbore does
not model, such as `response_format={"type": "json_object"}` for provider-side JSON
enforcement). These reach the provider call uniformly: a one-shot model step and a
model+tools tool-loop step resolve the same per-provider config, so JSON-mode and
transport settings behave identically on both paths.

**Fallback is governed, not blind.** A profile lists ordered targets and a closed set
of `fallback_on` reasons (`timeout`, `rate_limit`, `server_error`,
`provider_unavailable`). Provider exceptions are classified before any fallback
decision. Auth/config problems halt with `model_config_error`; a model returning
unusable output halts with `model_error`; an exhausted chain halts with
`model_unavailable`. Drawbore never falls back on a broken contract by default.

**A non-JSON response is diagnosable, and retried once.** When a model returns a 200
whose body is empty or not the JSON object the step expects, the `model_error` reason
now carries a short, bounded excerpt of that offending output (the model's own failed
text, truncated to a fixed length), so the failure is diagnosable from the halt reason
and audit record without dumping unbounded content. Because an empty or truncated body
is often a transient hiccup, a one-shot model call is re-attempted **once** on the same
model before halting — a single, always-on, bounded retry, not a fallback and not a
toggle. If the retry still returns unusable output the step halts with `model_error`:
halt-and-escalate is never weakened. A structural mismatch (a response of the wrong
shape, or valid JSON that is not an object) is not transient and fails closed
immediately. A model+tools tool-loop step is not retried this way, because re-running a
loop could replay tool side effects.

**Model+tools loops fall back safely.** A model+tools agent resolves through the same
runtime. Provider failure *before any tool call* may try the next model; once a tool
has run, a provider failure fails closed — Drawbore will not replay tool side effects
across providers. Tool failures and denials always abort immediately; fallback never
lets a model recover around a tripped control.

**The pipeline manifest stays runtime-free.** A reviewed manifest may carry
`"model": "profile:judgment"` as an agent declaration string. It never carries
credentials, gateways, engines, or provider routing knobs. Pipeline config says what
capability the workflow asked for; runtime config says how this deployment serves it.

**The audit is legible.** Each model step records its declared refs, the concrete
attempts and their outcomes, and the selected model — never API keys, headers, or
secret values. A compliance reader can tell "we configured this wrong" from
"OpenRouter timed out" from "the model returned invalid output."

**In tests, nothing calls a provider.** `pipeline.test_mode(...)` resolves `profile:*`
for real but answers from your mocks; a fake credential checker keeps CI key-free, and
a missing mock fails closed rather than reaching a live provider.
