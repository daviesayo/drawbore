---
title: "Pipelines"
description: "Compose deterministic agents into a typed, schema-checked pipeline."
---

A **pipeline** is an ordered set of **agents**. Each agent declares a typed
input and output. Drawbore validates the data crossing every boundary, so a step
can never receive or emit the wrong shape of data.

## Define agents

```python
from pydantic import BaseModel
from drawbore import agent

class Seed(BaseModel):
    value: int

class Doubled(BaseModel):
    doubled: int

@agent(input=Seed, output=Doubled)
async def double(seed: Seed) -> Doubled:
    return Doubled(doubled=seed.value * 2)
```

## Compose and run

```python
from drawbore import Pipeline, From

pipeline = Pipeline(name="example")
pipeline.add(double)

result = await pipeline.run(Seed(value=5))
assert result.status == "completed"
assert result.outputs["double"].doubled == 10
```

## Bind data between steps

When a step needs fields from earlier steps, bind them explicitly with `From`:

```python
pipeline.add(decide, inputs={"doubled": From("double.doubled")})
```

## Branch and join

Gate a step on an upstream field with `When` — the step runs only when the condition
holds; otherwise it is skipped and the skip is explained in the audit trace:

```python
from drawbore import Pipeline, From, When, Join

pipeline.add(enhanced_dd, inputs={"level": From("risk.level")},
             when=When("risk.level", equals="high"))
pipeline.add(standard_review, inputs={"level": From("risk.level")},
             when=When("risk.level", in_=("low", "medium")))
```

Merge mutually-exclusive branches with an explicit `Join`:

```python
pipeline.add(Join("review", sources=["enhanced_dd", "standard_review"],
                  policy="exactly_one", output=Review))
pipeline.add(writer, inputs={"verdict": From("review.verdict")})
```

`When` supports `equals`, `in_`, `is_true`, `gt`, `lt`. For richer logic, compute a
typed field in a routing step and gate on it. Join policies: `exactly_one`,
`first_by_priority`, `all_present`. See the tested
`examples/risk_branch/` for a full runnable branch-and-join pipeline.

## Binding inputs in fan-in topologies

When you call `pipeline.add(agent)` with no `inputs=` argument, Drawbore uses
**predecessor-output mode**: the step's input is taken from the output of the
step immediately preceding it in **declaration order** — not from any
topological source.

In a sequential pipeline that is the natural choice. In a fan-in topology it is
a silent footgun.

**The problem.** Suppose you fork from a `router` step and add two parallel
branches:

```python
pipeline.add(router)
pipeline.add(branch_a, inputs={"x": From("router.x")})
pipeline.add(branch_b)          # no inputs= — looks like it reads from router
pipeline.add(Join("merged", sources=["branch_a", "branch_b"],
                  policy="all_present", output=MergedResult,
                  inputs={"a_out": From("branch_a.result"),
                          "b_out": From("branch_b.result")}))
```

`branch_b` has no bindings. In declaration order the step immediately before it
is `branch_a`, so predecessor-output mode delivers `branch_a`'s output to
`branch_b` — not `router`'s output. At run time Drawbore validates the payload
against `branch_b`'s input schema. If `branch_a`'s output shape does not match
`branch_b`'s input, the run **halts** with `halt_code="schema_violation"` naming
`branch_b`'s input schema. The symptom points at the wrong place; the root cause
is the missing binding.

Note: Drawbore catches this at run time via schema validation and halts rather
than continuing with bad data. There is no registration-time warning when a
fan-in branch omits bindings — the static check at `Pipeline.add` runs only when
bindings are explicitly declared.

**The rule.** In any fan-in topology, declare explicit `From(...)` bindings on
**every** branch. Do not rely on predecessor-output mode for a step that follows
a parallel branch:

```python
pipeline.add(router)
pipeline.add(branch_a, inputs={"x": From("router.x")})
pipeline.add(branch_b, inputs={"x": From("router.x")})  # explicit — reads from router
pipeline.add(Join("merged", sources=["branch_a", "branch_b"],
                  policy="all_present", output=MergedResult,
                  inputs={"a_out": From("branch_a.result"),
                          "b_out": From("branch_b.result")}))
```

`From("agent.field")` binds a single field; `From("agent")` binds the whole
output object. Both forms are accepted on `inputs=`.

## What Drawbore guarantees

- **Static check** (when you build the pipeline): every binding's source type
  must match the target type, or the pipeline is rejected before it runs.
  Compatibility is **directional** and only widens in the safe direction. A
  narrowed output satisfies a wider input: an upstream field typed
  `Literal["USD", "EUR", "GBP"]` binds to a downstream field typed `str` (the
  literal value is always a valid `str`), so consumers need not repeat the exact
  literal set. The reverse is refused: a `str` output bound to a
  `Literal["USD", "EUR", "GBP"]` input is rejected, because a plain `str` is not
  guaranteed to be one of the allowed values.
- **Runtime check** (at every step): inputs and outputs are validated; on any
  mismatch the run **halts** and reports exactly which step failed and why —
  it does not continue with bad data.
