---
title: "Taint and trust"
description: "Refuse to exfiltrate untrusted data — the lethal-trifecta breaker (read untrusted data, act on it, send data out) as a runtime guarantee."
---

**When to use this:** your pipeline ingests data you do not control — a fetched web page, an
email, an MCP server's response — and also has tools that can send data outward
(`http_post`, email, an external write). The taint breaker refuses to invoke an
exfil-capable tool while the current step is handling untrusted data, deterministically and
without a screener model.

Declare two facts on your tools:

```python
from drawbore.tools import ToolRegistry

reg = ToolRegistry()
reg.register_mcp_tool("docs:fetch", handler)                           # untrusted-source by default
reg.register_tool("http_post", handler, exfil_capable=True)            # a sink
```

The same two facts belong on MCP tools, and an MCP server is the most likely place an
outward-writing tool comes from. Declare them per tool on `register_mcp_server` so the
sink-gate protects an MCP notifier exactly as it protects a custom one:

```python
from drawbore.tools import TrustLabel

await register_mcp_server(
    reg, name="slack", url="https://slack.com/mcp",
    allowed_tools=["send_message", "read_status"], client=client,
    exfil_capable={"send_message": True},              # an MCP sink
    source_trust={"read_status": TrustLabel.TRUSTED},  # an internal read you trust
)
```

A tool you do not name keeps the fail-safe MCP default: untrusted-source and not a sink.

A step's trust scope starts from its inputs; invoking an untrusted-source tool taints the
step; a downstream step seeded from a tainted output starts untrusted. Any `exfil_capable`
call under an untrusted scope halts with `taint_violation`. A `When` predicate that reads a
tainted output halts with `condition_tainted` — untrusted data can never steer control flow.

The initial input is `TRUSTED` by default. For document or email triage, declare it untrusted
up front:

```python
from drawbore.tools import TrustLabel

await pipeline.run(initial, initial_trust=TrustLabel.UNTRUSTED)
```

`exfil_capable` is a whole-tool fact: it gates every operation of that tool. If a tool mixes
a benign read operation with an outward write, split it into two tools so the read is not
over-blocked.

**Tools called from the agentic loop.** When a model-backed agent
[drives a tool loop](/guide/agentic-tool-loop), every tool the model calls reaches its
handler through the same proxy as a deterministic agent's call — so the taint breaker is
enforced identically. Invoking an untrusted-source tool taints the step, and an
`exfil_capable` call under an untrusted scope halts `taint_violation`, whether the call came
from your code or from the model mid-completion. The model sees each tool under a
provider-safe alias, but trust scope, the sink-gate, the one-time token, and the audit trail
all stay keyed on the canonical ref, so the alias never weakens the breaker.

One refusal *shape* differs by path, and it changes which halt code an operator alerts on. In
the loop the model is only ever offered the agent's *declared* tools. A call the model makes
to anything else — a registered-but-undeclared tool, or an invented alias that maps to no
declared tool — never reaches the proxy, so it cannot raise a proxy scope denial; it fails
closed at the model boundary and halts `model_error`. A deterministic agent that calls a
registered-but-undeclared tool directly still halts `tool_access`. Same fail-closed outcome,
different halt code: alert on both `taint_violation` and `model_error` for the loop path, and
`tool_access` for the direct path. See [Branching on a halt](/guide/reliability#branching-on-a-halt)
for the full halt-code vocabulary.

**Honest scope.** Taint is whole-object (no field-level declassification yet). The guarantee
assumes tool calls within a step run one at a time (which is how the runtime executes them),
so the taint from one call is always visible to the next. Retrieving an untrusted-origin
payload through `evidence://retrieve` is a known gap (the evidence store does not yet carry
trust). A green run proves refusal on the paths it exercises; the structural guarantee comes
from the fact that every tool call passes through one enforcement point.
